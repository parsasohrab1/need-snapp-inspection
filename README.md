# اسنپ‌بازرس

اعزام بازرس شخص ثالث روی برنامه بازرسی و آزمون (ITP)، با الگوی پیشنهاد و پذیرش شبیه سفر: مدارک باید آماده باشد، بازرس واجد شرایط و نزدیک کارگاه پیشنهاد را می‌بیند، پذیرش اول بازدید را قفل می‌کند، و گزارش بازدید (IVR) با چک‌لیست، عکس و محدوده کارگاه بسته می‌شود.

سطح بلوغ این نسخه: **TRL 5** برای حلقه یکپارچه در محیط شبیه‌سازی‌شده کارگاه. جزئیات و حد ادعا در [docs/TRL.md](docs/TRL.md).

## اجرا

```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8077
```

مرورگر: <http://127.0.0.1:8077>

گذرواژه همه حساب‌های نمایشی `demo1234` است.

| کاربر | نقش |
| --- | --- |
| `coordinator` | هماهنگ‌کننده اعزام |
| `manager` | مدیر پروژه |
| `unit.manager` | مدیر واحد |
| `inspector.reza` | بازرس جوش، نزدیک کارگاه |
| `vendor` | نماینده ماشین‌سازی البرز |
| `buyer` | نماینده کارفرما |
| `admin` | مدیر سامانه |

کارفرماهای پیش‌فرض: پتروشیمی بندر امام، پالایشگاه آبادان، پتروشیمی خارک و شرکت نفت ستاره. محیط نمونه یک سفارش ساخت مخزن، مبدل، اسپول و شاسی با ۸ بازرس و ۴۰ نقطه ITP دارد.

## مسیر نمایش

1. با سازنده وارد شوید. نقطه برنامه‌ریزی‌شده‌ای که مدارکش کامل است را آماده کنید.
2. با هماهنگ‌کننده همان نقطه را اعزام کنید.
3. با `inspector.reza` پیشنهاد جوش باز را بپذیرید، موقعیت دستگاه را فعال و حضور در کارگاه را تأیید کنید، سپس چک‌لیست و عکس را بفرستید.
4. ثبت حضور بیرون از فنس ۸۰۰ متری از سوی سرور رد می‌شود.
5. کارفرما فرم IN را ثبت می‌کند؛ مدیر پروژه و سپس مدیر واحد با مهر و امضا آن را تأیید می‌کنند و سامانه پیشنهاد را به بازرسان واجدشرایط می‌فرستد. هر مرحله می‌تواند درخواست را با دلیل به مرحله قبل برگرداند.
6. پس از گزارش بازرس، گزارش از مدیر پروژه به مدیر واحد و سپس کارفرما می‌رسد. رد گزارش با توضیح، آن را به کارتابل مدیر پروژه برمی‌گرداند؛ تأیید نهایی کارفرما Claim و صورت‌وضعیت را ایجاد می‌کند.
7. فرم IN با انتخاب موقعیت کارفرما به فارسی یا انگلیسی نمایش داده می‌شود. تصویر مهر و امضای مدیر پروژه و مدیر واحد در تأیید درخواست بارگذاری می‌شود.
8. میزکار مدیر پروژه، تعداد ITPهای ثبت‌شده برای هر پروژه (بر مبنای تجهیزات دارای نقاط بازرسی) و تعداد ردیف‌های ITP را در جدول و نمودار نشان می‌دهد. دسترسی سازنده به ابزارهای مدیریتی و مختصات بازرسان محدود است.

دسترسی به GPS در مرورگر نیازمند اجازه کاربر و در محیط عملیاتی HTTPS است؛ روی `localhost` برای تست توسعه فعال است.
